## 关键判断（可被推翻的部分）

**1. 为什么不用生图？**
这页的硬约束是棋盘拓扑：多格连体、单末端箭头、方向必须与关卡数据一致。
生图模型画不对（本项目此前在 ArrowLine 上吃过双向箭头的亏）。所以选择
**确定性 3D 渲染**：几何来自数据，材质来自物理，文字来自 DOM。代价是背景细节不如生图丰富，
但这页本来就不需要复杂背景。

**2. 和 `Docs/DesignSystem.md` v6 的冲突，必须提前说清**
v6 §0 定的是"真·干净扁平，不做立体"。这版做的是**软胶立体（哑光）**，
因为扁平方向已经被你判为"像工具应用"。本轮沿用 v6 的**色彩角色分工、字号阶梯、间距栅格**，
但推翻了"扁平"这一条。要么你认可这个转向、我回头把 DesignSystem.md 改到 v7；
要么回退扁平，我按 v6 重做。**这条需要你定，我不替你决定。**

**3. 色板提了彩度**
v6 §1.4 的 6 组色偏灰（为了在奶油底上"降明度"）。实际渲染出来发闷，
本轮把饱和度乘 1.22、明度乘 1.02。参照物是原版对局页的饱和度。

## 复现

```bash
# 1. 提取棋盘（真实关卡 → 数据）
python tools/extract_level.py 20260817_v1_Level12_easy.json

# 2. 起本地服务（ES module 需要 http；站点根必须是 UI_r1_board/）
python -m http.server 8792 --bind 127.0.0.1

# 3. 截图（Playwright + 本机 Chrome，SwiftShader 软件 WebGL）
NODE_PATH=<workbuddy node workspace>/node_modules \
PAGE_URL=http://127.0.0.1:8792/render/page.html node tools/shoot.js
```

产物：`out/game_2x.png`（2160×3840）。设计档规格化到 1080×1920 用 `preview/` 里的脚本参数即可。
