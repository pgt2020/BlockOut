# R2 切图与透明素材 —— 试样报告（未通过，禁止批量）

## 1. 实际可调用的工具盘点（动手前已列，此处归档）

| 能力 | 工具 | 状态 | 真实限制 |
|---|---|---|---|
| 通用抠图 / 前景提取 | `buddy-image-processing` 的 `matting`（云模型） | ✅ 可调用 | 只返回透明底主体；**奶油/米色低对比底板会被当背景吃掉**；不保留原始尺寸/位置元数据 |
| 去文字 / 去水印 | 同技能 `erase` | ✅ 可调用 | 面向文字水印，不是通用物体移除 |
| 修复缺失区域 | 同技能 `restore` | ✅ 可调用 | 面向老照片划痕，补背景不保证连续 |
| 图像增强 / 放大 | 同技能 `enhance` | ✅ 可调用 | 不产生新结构 |
| 参考重生成（图生图） | `ImageGen`（image1 + input_fidelity） | ✅ 可调用，需积分（约 5–10/张） | 会引入新细节，不保证与定稿逐像素一致 |
| 原生矢量 / 3D 绘制 | HTML+CSS / three.js | ✅ 可调用 | 尺寸、材质、阴影最可控；写实材质不如模型 |
| 确定性裁切 / 尺寸整理 / 图集 / 逐像素检查 | 本地 PIL + numpy | ✅ 可调用 | **仅技术用途，不冒充智能抠图或补绘** |

**明确不具备**：
- 局部 inpaint（移除物体并物理连续补全背景）的专用模型；
- 从扁平截图恢复原始分层（主体 / 阴影必须靠抠图或重绘拆分）；
- 能自动保留「被吃的浅色底板」并输出正确原尺寸的抠图后处理。

## 2. 资源分类与处理方式（逐资源，不一刀切）

| 资源 | 选定方式 | 理由 |
|---|---|---|

| 关卡节点（灰锁/紫/绿/红） | 建议**原生矢量绘制** | 几何简单、状态多（锁定/当前/完成），矢量可控 |

## 3. 三个试样实测结果

源图裁切在 `samples/src_*.png`，抠图结果 `samples/mat_*.png`，三底对比 `samples/tri_*.png`，补底修复 `samples/fix_*.png`。

### 3.1 绿色按钮 —— ✅ 通过
- Alpha：=0 占 13.8%，=255 占 83.0%，半透明 3.1%；四角透明，中心不透明。
- 黑底无花园杂边；奶油描边 + 柔和投影保留完整；文字「第 37 关」与箭头清晰。
- 结论：可直接作为透明素材，尺寸材质与定稿一致。

### 3.2 任务圆钮 —— ⚠️ 未通过
- 抠图把圆形奶油底座整体吃掉，只剩剪贴板 + 红点 + 中文标签。
- 用原生矢量补了圆底（`samples/fix_icon_task.png`），黑/白/游戏底三底均正常。
- 但补底是**估算半径与中心**，无原始数据支撑；拼回后尺寸偏小、位置偏右。
- 结论：单独可用，**不足以保持定稿一致性**。

### 3.3 底部导航卡 —— ⚠️ 未通过
- 抠图把整块奶油卡底吃掉，只剩房子图标 + 文字 + 绿下划线。
- 用原生矢量补了整卡底板（`samples/fix_panel_tab.png`），三底均正常。
- 但底板圆角/阴影/尺寸是估算，与定稿原卡有差距；拼回后卡片明显偏小。
- 结论：单独可用，**不足以保持定稿一致性**。

## 4. 拼回定稿对比（关键证据）

`samples/reassemble_compare.png`：左=用户参考原图，右=用真实抠图素材拼回（仅换 3 个组件）。

暴露的问题：
1. **背景不是同一张**：参考图是近景花丛 + 右侧画架 + 平缓路面；项目已有素材是近景石板路 + 左侧拱廊占画面。构图不一致，切图无法解决。
2. 任务钮尺寸偏小、位置偏右（圆底丢失后估算尺寸）。
3. 首页卡比例偏小（底板补绘尺寸估算）。
4. 仅按钮尺寸与材质基本吻合。

## 5. 结论（按用户规则，不宣布完成）

**试样未整体通过，禁止批量处理。**

阻塞项：
- **背景素材不符合定稿构图** —— 需要重新生成贴合用户参考的花园场景（ImageGen 生图，需积分，须用户确认），或从用户原始高分辨率图提取（当前参考图带 UI，不可直接用）。
- **浅色底板的抠图保真** —— 奶油/米色组件需改为原生矢量重绘，不能依赖 matting。
- **定稿一致性** —— 拼回证明单独好看的素材不等于对位正确；需要原始组件尺寸/锚点数据。

因此：**切图未完成**，只完成了 3 个试样与问题定位。等待用户裁决（是否接受 ImageGen 重生成背景 + 组件改矢量重绘）。
