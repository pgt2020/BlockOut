### C02 / P0：Prefab 内部引用与场景外部对象 ID 错误

静态扫描发现本轮交付的 10 个 Prefab 均有非零本地 fileID 无对应对象声明的问题，范围为 `Assets/BlockOut/Resources/Prefabs/` 下 App、Board 和 UI 资产。

例：`UI/BlockOutHomePage.prefab` 的 m_Component 引用 4，但 RectTransform 声明 ID 为 1000000000004000；m_Children 引用 6、8、10，m_Father 仍引用 4，均未与声明映射统一。

`Assets/BlockOut/Scenes/Launcher.unity:159` 引用 AppRoot 根对象 1000000000000000，但 `App/BlockOutAppRoot.prefab` 的根对象声明为 1000000000001000。

修复：修正 `Tools/gen_blockout_assets.py` 等生成工具的 ID 映射并重新产出资产，保持资产 GUID；核对组件、父子节点、脚本、跨资产对象 ID。不得通过运行时回退创建掩盖坏资产。

验收：每个非零本地引用都能解析，跨资产引用定位到实际对象；不是只检查 GUID 文件存在。

### C03 / P1：页面组件脚本绑定

`Assets/BlockOut/Runtime/UI/BlockOutUIPrefabRegistry.cs` 同时声明静态注册表和 BlockOutPageView MonoBehaviour；页面 Prefab 的 m_Script 指向这个文件的 GUID。可挂载类与脚本文件名不对应。

修复：将 BlockOutPageView 拆入同名脚本，生成正确 meta 并更新所有 Prefab 组件引用；全面检查新增 MonoBehaviour 和 ScriptableObject 的文件名与绑定。

验收：可挂载组件有正确 MonoScript，页面根有实际有效视图组件，不能只用 AddComponent 回退补齐。

### C04 / P1：R11 页面 Prefab 迁移仍未完成

- 逐页接通入口，删除对应的旧整页构建代码，避免双份节点。

验收：固定布局能在 Prefab 中直接检查和调整；设置、结算和弹层也有真正使用的实例化路径。

### C05 / P0：保存失败的事务回滚被跳过

`Assets/BlockOut/Runtime/Infrastructure/Persistence/BlockOutProfileTransaction.cs:35` 在 service.Save 之前设置 finished=true，失败后调用 Rollback，但 Rollback 检查 finished 后直接返回。

修复：保存成功后才完成事务；失败必须实际恢复快照，结束状态只设置一次。同时处理 store.Set 后 Commit 失败留下的缓存中间态，避免后续其他保存把失败事务落盘。

验收：注入提交失败后，金币、道具、通关、进度和有效对局状态整体恢复；验证内存、后续另一次保存、重新加载三种结果。恢复存储仍失败时应保留可感知错误，不能谎报成功。

### C06 / P1：新旧档案对象并存，有覆盖进度风险

`BlockOutGameManager.Awake` 自行加载 Profile 并创建 Settings、Guide 等；随后 BindServices 替换 GM.Profile，只尝试重绑 Settlement。Settings 和 Guide 仍持有旧对象，并直接 profile.Save。设置变化或引导完成可能将旧档案覆盖新进度。

修复：只加载一次档案，注入后初始化持档案的系统，确保同一个对象；设置、引导、UI 的写入都进入存档服务。启动已加载的 Catalog 和已初始化的广告不要再由 GameManager 重复初始化。

验收：通关/购买后切换音效或完成引导，再重启，金币、道具和进度都保留；测试实际生产绑定路径。

### C07 / P1：结算与金币复活未接入完整事务

`BlockOutGameManager.OnLevelWon:766` 修改奖励、进度、通关和清局状态后忽略保存结果，继续通知 UI 成功。ReviveWithCoins 先扣币保存，再执行复活，存在分步落盘。

修复：结算的奖励、拼片、进度、清局一次提交；金币复活的扣款、资格、生命/时间和有效对局一次提交。保存失败恢复相关运行态与档案，提供失败提示和重试策略。挑战身份/幂等规则必须兼容合法重玩奖励，不能用“本关已通关”一律禁止重玩奖励。

验收：通过生产入口或生产共用服务模拟保存失败、重复回调、空棋盘补结算和合法重玩；不能只在测试里另写一套正确流程。

### C08 / P1：LevelPlay 仍是占位

`Assets/BlockOut/Runtime/Infrastructure/Ads/LevelPlayAdAdapter.cs:49` 初始化和展示只有注释、日志，没有 SDK 调用和事件订阅，展示还直接调用自己的 OnAdShown。

修复：

- 正式聚合固定 Unity LevelPlay / ironSource，不迁入 MAX 初始化。
- 确定 SDK 来源与版本，导入兼容依赖，按选定版本官方 API 完成初始化、加载、展示、失败、关闭、奖励及释放。
- 配置按平台区分，App Key、广告单元与 Placement 的含义遵循选定 SDK，不混用；缺实际凭据单列。
- 处理线程、加载重试、重复事件、展示期间抢占和跨局旧回调。
- 依据实际 SDK 事件顺序处理关闭与奖励，避免提前清空请求丢有效奖励；关闭本身不发奖。
- adsEnabled=false 必须真正停止广告创建与初始化，不能因为填了凭据就绕过总开关。

验收：代码、包、配置、初始化、真机奖励回调分别报告；缺凭据不能作为 SDK 和适配代码未实现的总括理由。不复制参考工程凭据。

### C09 / P1：发布门禁没有核对实际入口配置

### C10 / P1：预加载、生命周期、服务与测试未完整接通

预加载：启动序列的 DeferredPreload 在页面装配前执行；首屏必需清单没有实际执行和校验；deferredAudio 被合并到 Sprite 加载循环。按资源类型和阶段加载，必需失败有处理路径，首屏可用后再延后预热，取消不得回填旧页面。

生命周期：EnterAdOverlay、ExitAdOverlay、NotifyRestarting、NotifyQuitting 等在 Runtime 只有定义，缺实际业务调用；GameManager 和协调器仍各自处理前后台。统一暂停状态归属，接入真实广告、暂停、重开和退出路径；检查正常销毁、启动失败和重建时的资源及订阅释放。

服务注册：启动按 BlockOutAnalyticsService 具体类型注册，AppRoot 按 IAnalyticsService 解析，当前取不到。统一按消费接口注册或明确注册规则，检查其他服务。

测试：

- ServiceRegistry 测试 Register(store) 注册具体类型，却按 IProfileStore 解析，与生产实现不符。
- “恢复已通关存档”测试使用先前已 SettleWin 的同一个 settlement，却断言 HasPendingReward 为 false。
- 必需 Prefab 缺失使用 Assert.Ignore，会跳过交付错误，应明确失败。
- 事务测试不能只复演手写流程，需要覆盖实际业务服务和失败状态。
- 分清代码已写与实际执行，不因测试数量就宣称覆盖完成。

检查工具：补本地 fileID、跨资产对象 ID、MonoScript 绑定、程序集实际依赖。更新原需求表、交付文档的状态，未完成项不能继续统一写静态已核对。
