# ArtOut 玩法对齐复查整改清单

检查日期：2026-10-20。基于当前工作区未提交的实现。只静态阅读源码、配置、测试与交付记录；未执行 Unity 刷新、编译、Play Mode、测试、Console 或外部 C# 构建。本轮仅新增此报告，不修改玩法代码。

结论：有实质进展，但仍有可直接从生产调用路径确认的问题，不能以“阶段 A–D 全完成”作为验收结论。以下路径相对于 `E:/UnityProject/MutiplayGame/BlockOut/`；行号对应本次检查版本。P1 应优先修复，P2 为体验对齐与交付完整性问题。

## R01 / P1：复活未恢复棋盘输入，计时器模态标记也未清除

- 位置：`Assets/BlockOut/Runtime/Gameplay/BlockOutGameManager.cs` 的 FeedbackWrongTap（592–598）、UpdateTimeFailTimer（1195）、ApplyRevive（974–990）；`Assets/BlockOut/Runtime/UI/BlockOutUIController.cs` 的 OnReviveClicked（676–699）。
- 证据：误点反馈将 BoardView 输入锁定，失败后回位回调因 State=Lost 不解锁；倒计时失败也显式锁输入。ApplyRevive 只补心/加时并切 Ready，没有恢复输入。UI 三条复活成功路径只关闭 FailLayer，没有调用 SyncModalFlag；OnReviveStateChanged 也没有消费者完成这些工作。
- 影响：本次游戏中失败后复活，界面虽关闭，方块仍点不动；即使另一路偶然解锁，时间模式还可能因 ModalPopupOpen=true 永远停表。
- 修复：复活成功统一恢复完整运行状态，按当前暂停/工具/弹层状态释放失败锁；关闭失败层同时刷新模态标记。不要无条件解开其他原因的锁。
- 验收：生命/时间两种模式，免费/金币复活各验证可点击、可计时、再次失败再次复活；恢复失败存档也走同一语义。

## R02 / P1：本地 JSON 的多项配置仅有声明，没有接到实际消费者

- 位置：`Runtime/Core/BlockOutContentConfig.cs` 的 Apply（80–91）及复活常量；`Runtime/Gameplay/BlockOutGameManager.cs` 的 ConfigUseTimeFailMode（121）、GameTimeSeconds（124）、LoadLevel（334、349）、FinalizeRemoval（662）、Specials.LoadExtras；`Runtime/Core/BlockOutGameRules.cs:17`。以上均位于 `Assets/BlockOut/`。
- 证据：JSON useTimeFailMode 被写入 ContentConfig.UseTimeFailModeDefault，但 GM 新局读的是从未赋值的 ConfigUseTimeFailMode=false。gameTimeSeconds 没接到 GM 120 秒兜底；maxLives 仍硬编码 3；revive 费用、免费关数、补心与加时仍读 const；freeLifeCount、limitPerRun 没有实际消费者。enableCombo/enableSpecialBlocks 没有用于行为开关，消除仍计连击并加载特殊块。
- 修复：建立字段→加载→业务→UI 的完整映射，让本地配置真实生效。若某字段暂不支持，明确拒绝非默认值，不允许校验通过却静默忽略。新挑战读配置，旧局恢复保留原失败模式。
- 同时修复：GetLevelReward 将有效配置奖励 0 当作无配置，错误回退关卡奖励；0 是合法禁发奖励值，应保留。
- 验收：仅修改 JSON 就能开启时间模式并改变复活费用/加时；无 gametime 的关使用配置兜底；默认关闭连击与特殊块。UI 与业务一致，已有档案资产不被重置。

## R03 / P1：魔法棒链式目标被第二次过滤破坏

- 位置：`Assets/BlockOut/Runtime/Gameplay/BlockOutToolController.cs:144–155`；`BlockOutGameManager.cs:721–724、750`。
- 证据：rules.PickMagicTargets 已在模拟移除后的占用上选出 A→B→C；但之后调用 isActionable(b)，GM 传入的 IsPlayerActionable 又以未改变的真实棋盘执行 Rules.CanMove(b)。因此 B/C 仍被判受阻而过滤。
- 影响：一条长度 6 的可依次消除链，魔法棒可能只消除最外侧 1 块，与参考效果不同。现有测试使用 `_ => true`，绕过生产过滤器，无法发现此问题。
- 修复：普通模式直接使用规则层的链式目标；若保留特殊规则，把过滤纳入同一模拟状态，不能再用原棋盘可动性二次否决链式结果。
- 验收：通过生产选取路径验证 A→B→C 三连与六连，正确消除且只扣一次库存。

## R04 / P1：魔法动画在暂停/失败后仍推进逻辑，并且绕过统一胜利等待

- 位置：`Assets/BlockOut/Runtime/Gameplay/BlockOutGameManager.cs:768–840`。
- 证据：MagicTargetRoutine 用 WaitForSeconds 等待星路径和脉冲后，仅检查 token/Active，不检查 IsPaused 或 Lost，然后 Rules.Remove。暂停只设置布尔量，没有停止全局时间；BoardView 的星路径可以暂停，但 GM 的等待不会同步暂停。MagicRoutine 结束时直接 OnLevelWon，没有经过 MaybeWin 的 inFlightFlyOuts 检查；UseMagic 也没有阻止普通飞出期间启动工具。
- 影响：暂停时逻辑消块而视觉未命中；限时已失败后魔法继续改棋盘，极端情况下形成 Lost+空棋盘；与普通在途动画重叠时可能提前结算。当前还等魔法所有飞出结束才放开普通输入，与参考“星命中处理完解除工具锁、飞出可继续”的时机不同。
- 修复：工具动画统一用可暂停、可取消的完成回调；失败立即取消后续逻辑提交。工具启动条件和解锁时机对照参考。正常/工具都经同一个胜利入口，等待所有必要在途演出。
- 验收：星飞行/命中阶段分别暂停、切后台、超时、重开；旧回调不得消块或解锁新局。普通飞出与魔法重叠时只在应有时机结算一次。

## R05 / P1：金币复活仍不是一次完整事务

- 位置：`Assets/BlockOut/Runtime/Gameplay/BlockOutGameManager.cs:946–990`。
- 证据：ReviveWithCoins 先 CommitProfileChange 扣币落盘，再 ApplyRevive 修改生命/时间/状态，最后另调 SaveActiveRun；后者忽略保存返回值。
- 影响：第一次保存成功、第二次失败或中途退出时，金币已扣而持久化对局仍失败；ApplyRevive 仍返回 true。
- 修复：扣币、生命/时间、RunLost、运行态、复活记录与有效对局快照同一次事务提交；失败恢复档案、Rules 和 GM 状态，不关闭失败层。
- 验收：注入提交失败后金币与失败局完整保持；重新加载结果一致，下一次合法复活仍可进行。

## R06 / P1：结算保存失败后仍发出胜利事件，没有可用的失败恢复

- 位置：`Assets/BlockOut/Runtime/Gameplay/BlockOutGameManager.cs:845–887`；`Assets/BlockOut/Runtime/UI/BlockOutUIController.cs:130` 附近订阅表。
- 证据：OnLevelWon 提前设置 State=Won；事务中将 runPlayable=false，并修改 Assembly/Settlement。保存失败只回滚 Profile，随后仍设置 LastRewardCoins、播放胜利声并无条件触发 OnLevelWinned。OnSaveFailed 事件没有 UI 订阅。
- 影响：显示获得奖励并允许下一关，但金币/进度未保存；内存章节状态、运行态与回滚后的档案不一致，缺少重试途径。
- 修复：只有事务成功才发送胜利成功通知；失败恢复或保留可重试的待结算状态，阻止继续下一关覆盖现场。错误提示必须接入 UI。幂等以本次挑战为单位，不禁止合法重玩奖励。
- 验收：保存失败不假报领奖成功；重试/重启不重复发奖、不丢结算；实际 GM 入口验证，不能只测试独立 ProfileTransaction。

## R07 / P1：道具消费失败没有恢复运行库存，魔法中途消除也未及时写入对局

- 位置：`Assets/BlockOut/Runtime/Gameplay/BlockOutGameManager.cs:687–698、706–715、745–760、821–839`。
- 证据：Tools 在事务前扣库存/改棋盘，ToolsToProfile 忽略 CommitProfileChange 的 bool；失败只恢复 Profile，不恢复 Tools、已提示集合或棋盘，演出继续。MagicTargetRoutine 每个目标移除后只 ToolsToProfile，未 CaptureRunProgress/SaveActiveRun，正常情况下直到所有魔法动画结束才更新 RunRemoved。
- 影响：消费失败仍消块且内存库存已扣；后续保存会把失败消费重新写入。魔法部分目标已消除但进程终止时，可能保存了扣费而没有保存对应消除进度。
- 修复：道具消费与逻辑效果使用明确提交状态，失败恢复所有相关模型并停止演出；每次承诺的逻辑消除持久化到一致的局内快照。
- 验收：提示/锤子/魔法消费保存失败都不产生半成功；魔法中途重启，已付费和已承诺消除相匹配。

## R08 / P2：重复误点被直接吞掉，错误标记不是参考的持久视觉

- 位置：`Assets/BlockOut/Runtime/Gameplay/BlockOutGameManager.cs:565–571`；`BlockOutBoardView.cs:295、797–807、871–891`。
- 证据：只有 LifeLost 或 !AlreadyMarked 才执行 FeedbackWrongTap，因此重复误点无撞击/错误音效。箭头仅 enabled 闪烁，没有错误色状态；红环 0.28 秒后消失，恢复存档重建也没有应用 WrongMarked 的视觉。
- 修复：重复误点仍反馈但不扣心，并区分提示文字，不能每次显示“已扣 1 心”。保持错误箭头标记直到该块移除，重建可恢复；闪烁参数读取 JSON。误点与提示位置动画也要服从暂停/取消。
- 验收：同块三次误点只扣一次心、三次有反馈；错误标记与存档一致；暂停误点动画不继续回位或错误解锁。

## R09 / P1：游戏棋盘缩放和手势抑制没有接入

- 位置：`Assets/BlockOut/Runtime/Bootstrap/BlockOutAppBuilder.cs` 棋盘装配；`Assets/BlockOut/Runtime/Gameplay/BlockOutBoardView.cs:281、690`；`Assets/BlockOut/Runtime/UI/BlockOutUIManager.cs:1243`。

- 修复：在游戏 BoardArea 接入手势控制，拖动/双指排除点击，结束后按配置抑制；正确处理 UI 遮挡与缩放坐标映射。参考近邻选块策略也应接实际输入，不只是保留按格热区。
- 验收：游戏页而非收藏页双指缩放可用；拖动及双指变单指不消块、不跳位；弹窗期间不穿透。

## R10 / P2：锤子和提示演出尚未按参考落实
