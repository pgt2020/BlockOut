# BlockOut 工程化重构方案（R02）

版本：2026-10-16（第十一轮 · 工程化重构 P0 方案）
配套：《重构基线与依赖清单.md》。本文件是执行方案，逐条对应 R01–R23。

---

## 1. 总体策略

**分层替换、分阶段落地、存档与资源契约不变。**

| 原则 | 落地方式 |
| --- | --- |
| 不重设计玩法/经济/章节/视觉 | 只改组织方式与装配方式，业务逻辑逐行保留 |
| 不覆盖参考工程、不改 Packages/ProjectSettings 整套 | 仅改 `EditorBuildSettings.asset` 的场景列表 |
| 存档零丢失 | 旧键/字段/关卡 ID/hash 全部保留；新增能力走版本迁移 |
| 资源零丢失 | 移动文件用 `git mv`，`.meta`/GUID 随行；`Resources/` 路径保持兼容 |
| 不引入大型 DI 框架 | 自建轻量 `BlockOutServiceRegistry`（Bootstrap 组装） |
| 阶段报告不是停止点 | P0→P5 连续推进，缺外部凭据不阻塞独立工作 |

## 2. 目标程序集与依赖（目标态）

```text
BlockOut.Core                  （无依赖：规则/模型/关卡解析/求解/档案模型）
BlockOut.Rendering             → Core
BlockOut.Infrastructure.Ads    → Core, Contracts      （IAdProvider + LevelPlay 适配 + 开发替身）
BlockOut.Infrastructure.Persistence → Core            （存档/迁移/事务）
BlockOut.Infrastructure.Configuration → Core          （本地/远程配置）
BlockOut.Infrastructure.Resources → Core              （加载/缓存/预热）
BlockOut.Infrastructure.Audio → Core, Configuration   （音频服务）
BlockOut.Infrastructure.Analytics → Core, Contracts   （统计契约 + 模块矩阵）
BlockOut.Gameplay              → Core, Rendering, Infrastructure.*
BlockOut.UI                    → Core, Gameplay, Rendering, Infrastructure.*, Unity.ugui
BlockOut.Bootstrap             → 全部 Runtime 程序集 + Unity.ugui   （唯一组装点）
BlockOut.Editor                → Bootstrap + 各 Runtime（仅编辑器）
BlockOut.Tests.EditMode        → Core, Gameplay, Infrastructure.*
BlockOut.Tests.PlayMode        → Bootstrap, UI, Gameplay
```

约束（需求 §3）：Core 不引用 UI/SDK/编辑器；Gameplay 不直接引用具体 SDK；UI 不决定扣款与发奖；Bootstrap 负责组装实现。

**既有 asmdef 处置**：`BlockOut.Services` 随文件夹迁入 `Infrastructure/Ads` 并更名 `BlockOut.Infrastructure.Ads`（同步更新 Gameplay asmdef 引用与 `using`）。其余 4 个 asmdef 名称不变、只移动位置。

## 3. 启动时序设计（R03/R04）

```text
Launcher.unity（Build Settings 首场景，唯一）
└── GameObject "BlockOut_Launcher"  ← BlockOutLauncher（重复入口防护）
    └── 运行 BlockOutStartupSequence（显式步骤，带状态/进度/超时/失败策略）

Step 1  ApplicationConfig   帧率/输入/睡眠/区域文化/日志开关（按 StartupConfig）
Step 2  LocalConfig         读取 BlockOutStartupConfig 资产（Editor/Development/Release）
Step 3  ProfileMigration    存档版本迁移（v1→v2→v3 结构保留）
Step 4  ContentCatalog      关卡清单 + 关卡 JSON + extras
Step 5  OptionalServices    广告/统计按配置初始化；失败不永久卡住
Step 6  FirstScreenAssets   首屏 Prefab + 字体 + 必要音频
Step 7  AppReady            AppRoot 就绪，业务接受输入
Step 8  DeferredPreload     延迟预热（章节大图/特效/音频），空闲帧分摊
```

分支规则（R03 验收）：新用户 → 首页；有效旧局 → 棋盘；失败局 → 失败层；旧空棋盘胜利存档 → 补结算。相机/EventSystem 只建一份（AppRoot 持有，重复检测后销毁多余者）。

## 4. 生命周期统一（R06）

单一状态机 `BlockOutAppLifecycle`，替代 GameManager / UIController / Ads 各自改暂停状态：

| 状态 | 触发 | 行为 |
| --- | --- | --- |
| `Playing` | 就绪且前台 | 正常输入 |
| `UserPaused` | 玩家点暂停 | 锁输入、开暂停层、落盘；**前台回调不得解除** |
| `AutoPaused` | 切后台/失焦 | 落盘 + 置后台标记；回前台只补开暂停层，不 Resume |
| `AdOverlay` | 广告展示中 | 暂停计时与输入，关闭后恢复 |
| `Restarting` | 重开/切关 | 令牌自增，旧协程与回调全部失效 |
| `Quitting` | 放弃/退出 | 清对局存档、释放订阅、AppRoot 可显式销毁 |

旧局回调隔离继续依赖 `activeRunToken`（既有机制，不改）。

## 6. SDK 选型与缺口（R14/R15）

| 项 | 决定 |
| --- | --- |
| 广告聚合 | **Unity LevelPlay（ironSource）**，唯一入口；不引入 MAX/AdEngine |
| 接口 | 保留 `IAdProvider`，由 Bootstrap 按 `BlockOutAdConfig` 注入 `LevelPlayAdAdapter` |
| 回调模型 | 加载 / 展示 / 展示失败 / 关闭 / 奖励 **五类分别建模**；只有奖励回调发奖；关闭≠获奖；跨局回调不发放到新局 |
| 范围 | 仅激励广告（复活）；不默认启用 Banner/插屏 |
| 开发替身 | `DevelopmentAdProvider`（明确标注非正式），发布门禁阻止其进入正式包 |
| 统计归因 | 只建 `IAnalyticsService` 契约 + 模块矩阵；Firebase/Adjust/Facebook/ThinkingData 不批量搬入，无有效配置不启用 |
| 缺项 | LevelPlay SDK 包、App Key、Rewarded Placement ID、平台原生依赖、CMP/ATT 流程现状 —— 集中列缺项，不编造凭据、不复制参考工程凭据 |

## 7. 存档与事务（R13）

- `IProfileStore` 抽象存储（PlayerPrefs 实现 + 测试内存实现），`BlockOutSaveService` 负责读写、版本迁移、失败上报。
- 事务原语：`BeginTransaction()` → 内存试算 → `TrySave()` → 失败 `Rollback()`（恢复内存快照）。用于购买、复活扣币、结算发奖。
- 结算防重复：沿用 `MarkLevelCompleted` 去重 + `CurrentLevelIndex` 取 Max + 结算末 `ClearActiveRun`；本轮增加"已发奖标记"随存档一致落盘，重启不重复。
- 每次挑战/结算用"关卡 ID + 局令牌"区分合法重玩与重复回调，不用"该关已通关"禁止合法重玩奖励。

| 游戏 HUD | `Prefabs/UI/BlockOutGameHud.prefab` | `BlockOutGameHudView` |
| 收藏 | `Prefabs/UI/BlockOutCollectionPage.prefab` | `BlockOutCollectionView` |

- 静态层级（容器/分区/安全区根）进 Prefab；动态内容（棋盘格、收藏网格、章节大图裁切）由视图组件用既有工厂装配 —— 需求允许"保留必要的动态棋盘和区域生成"。

- 普通结算以 `09_component_spec.md §5.1` 为唯一基准（已定稿）。

## 9. 命名清理（R23）

旧名 → 新名映射在《重构基线与依赖清单.md》R23 节与交付文档中逐条登记。原则：

- 自有业务类/命名空间/asmdef/文件/Prefab/场景/配置资产/菜单项/构建工具 → `BlockOut` 语义。
- 公共代码、第三方 SDK、Unity API、许可证 → 保留原名与来源。
- **禁止全量替换**：旧存档键、关卡 ID/hash、远程配置键、分析事件名、外部后台契约，需要时提供旧名兼容读取。
- `Resources/ArtOut` 路径：新增集中资源目录映射 `BlockOutResourcePaths`，旧路径保留为兼容别名，不直接删目录造成丢档。
