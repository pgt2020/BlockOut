## 3. 唯一启动入口与启动顺序

- 唯一启用场景：`Assets/BlockOut/Scenes/Launcher.unity`（guid `a289df1e153c4b67a295ab66a07c2d4e`），`ProjectSettings/EditorBuildSettings.asset` 仅此一项启用。
- 入口链：`BlockOutLauncher`（Awake 重复入口防护，`Start` → `BootRoutine` 协程）→ `BlockOutStartupSequence.Run()`（8 个显式步骤，每步有状态/进度/超时，可选步骤失败降级不阻塞）→ 成功 `BlockOutAppBuilder.Build()` 装配 → `BlockOutAppRoot.MarkReady()` + 隐藏启动页；失败 `ShowBootFailure` 明确报错，不静默进游戏。
- 8 步：LocalConfig（应用帧率/后台/文化/日志）→ ApplicationConfig（ScriptableObject 环境档）→ ProfileMigration（存档加载 + v1→v2 迁移）→ ContentCatalog（关卡目录）→ OptionalServices（广告实现按配置选 LevelPlay 适配/开发替身/空实现）→ Resources（首屏预热）→ AppReady → DeferredPreload（空闲帧延后预热）。
- 生命周期：`BlockOutAppLifecycle` 状态机 Booting/Playing/UserPaused/AutoPaused/AdOverlay/Restarting/Quitting；主动暂停与切后台自动暂停分离，回前台只请求补开暂停层不擅自 Resume（对齐 GM 的 `OnPauseChanged`/`OnAppForegrounded`）。
- 旧入口已删：`RuntimeInitializeOnLoadMethod` 启动器、`Boot.unity` 空场景、`BlockOutBootstrapper`/`BlockOutGameBootstrap`、Assets/Scripts 下 11 个旧华容道文件（零引用验证记录见 §8）。

## 6. 存档兼容 / 事务 / 回退（R13）

- 键契约不变：`BlockOut_PlayerProfile_v2`（当前）/ `BlockOut_PlayerProfile_v1`（旧，迁移后保留不删，可回退）。
- v1→v2 迁移：补齐 `MaxLevelReached = Max(1, CurrentLevelIndex+1)`，迁移结果立即落盘 v2 键。
- `BlockOutSaveService`：唯一读写入口；`Save/TrySave` 返回 bool + `LastSaveError` + `OnSaveFailed` 事件；`Load` 任何异常退新档案不抛出。
- `BlockOutProfileTransaction`：JSON 快照，`Commit` 失败自动 `Rollback`，未提交即 `Dispose` = 放弃；金币/道具/拼片/进度/对局状态整体一致，不会半回滚。
- 对局语义：`HasActiveRun` + levelId + blockCount + hash 四要素校验恢复；`runPlayable` 保证已放弃/已通关的局不被 `Pause()` 写回（放弃后不恢复）；旧空棋盘存档（HasActiveRun + 0 块）走 `CompletePendingWin` 补结算，且 `MarkLevelCompleted` 去重 + `ClearActiveRun` 保证只结算一次。
- **本轮修复的注入缺陷**：`BlockOutSettlement` 原持有 Awake 时加载的旧 Profile 对象，`BindServices` 换成服务档案后奖励会加到旧对象并被服务档案整体覆写（金币丢失）。已修：`Settlement.BindProfile` 跟随服务档案 + 去掉 `SettleWin` 内部直写 PlayerPrefs（统一由 GM 结算序列末尾单点 `SaveProfile`，失败可感知、可随事务回滚）。

## 7. LevelPlay 接入（R14）

- 选型：Unity LevelPlay（ironSource），非 MAX；不迁入参考工程 MAX/AdEngine。
- 接入位置：`BlockOut.Infrastructure.Ads/LevelPlayAdAdapter.cs`（构造 `(appKey, rewardedPlacementId, isTestMode)`），由 `BlockOutStartupSequence.CreateAds()` 按 `BlockOutAdConfig` 注入；`IAdProvider` 契约保留在 `BlockOut.Contracts`。
- 五回调分别建模：`IronSourceEvents` 的 Loaded/Shown/ShowFailed/Closed/Rewarded 映射到 `AdShowCallbacks` 的 OnLoaded/OnShown/OnShowFailed/OnClosed/OnRewarded；requestId 单次获奖保证（`activeRewardFired`），新 Show 抢占使旧请求失效（防跨局发奖）；关闭≠获奖，奖励回调是唯一发奖依据；仅激励复活，Banner/插屏接口保留不默认启用。
- 缺凭据降级：`HasCredentials=false` 时初始即 NotLoaded，Show 走 OnShowFailed，**不模拟成功**；`BlockOutNullAdProvider` 空实现兜底；开发替身 `DevelopmentAdProvider` 仅开发配置可用，Release 门禁拦截。
- 外部配置待补：SDK 包未导入（无 IronSource 程序集，适配器按官方 API 签名写好、未编译验证）；App Key /  rewarded Placement ID 未配置（不编造）；平台原生依赖与 CMP/隐私流程现状未确认。以上见 §10 未完成事项。

## 11. 手动运行验收步骤（待用户执行）

1. Unity 打开工程，等待编译与导入完成，Console 应无 BlockOut 相关错误。
2. `Window → General → Test Runner`：运行 EditMode 全部（49 用例）与 PlayMode 全部（7 用例），预期全绿；有失败先修再继续。
3. 菜单 `BlockOut/发布检查/运行全部检查` 与 `BlockOut/工程检查/*`，逐项通过。
4. Play Mode 直接运行：应只进 Launcher → 启动页 → 首页；重复打开 Launcher 场景不得出现第二套 AppRoot。
5. 存档兼容：准备 v1 旧档（无 MaxLevelReached）启动一次，确认迁移后进度/金币/道具不变且 v1 键仍在。
6. 旧空棋盘旧档（HasActiveRun + RunBlockCount=0）：启动后走补结算一次，金币 +40、关卡标记、不再残留进行中局；再重启不重复发奖。
7. 动画中切后台并结束进程：恢复后该块仍在可继续点击；重开、放弃后不恢复已退出对局。
8. 魔法棒动画中保存退出：重启后恢复有效棋盘。
9. 三档分辨率（360×640 / 390×844 / 390×932）走查首页/HUD/收藏/商店/设置/结算布局。
10. 广告：开发档用替身演练奖励/取消/失败三路径；正式档缺凭据必须构建失败（发布门禁），不得静默使用模拟广告。
11. 真机（有条件时）：切后台/回前台暂停语义、激励广告真实回调、启动页时长体验。
